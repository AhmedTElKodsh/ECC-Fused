ECC-Fusion uses ECC as the base platform and adapts patterns from related agentic workflow systems. Attribution means "inspired by" unless a file explicitly states copied code and license compatibility.

| Source | Contribution | Local Surface | Status |
| --- | --- | --- | --- |
| ECC | Cross-harness install/runtime surface, skills, commands, hooks, manifests | repository structure, manifests, commands | Adapted |
| BMAD-METHOD | Advisory help, PRD to architecture to story chain | `/ecc-help`, Regular Path docs | Adapted |
| Superpowers | Clarify/spec/plan/TDD/review discipline | shared skill governance | Adapted |
| Matt Pocock skills | Small composable skills, anti-bloat, handoff, TDD | skill category and lint rules | Adapted |
| GSD Redux | State loop, fresh contexts, `.planning`, work packets | planning artifacts, state docs | Adapted |
| gstack | Review, QA, release, retro discipline | QA and release route requirements | Adapted |
| OpenSpec | Schemas and configurable workflows | JSON schemas and manifests | Adapted |
| GitHub Spec Kit | Spec-first guided facade behavior | Regular Path routing | Adapted |
| Agent OS | Concise indexed standards and context thrift | skill structure and docs | Adapted |
| Ralph | Bounded low-risk execution loop | Ralph eligibility and stop rules | Adapted |

Manifest entries must include `sourceInspiration` for adapted workflows.
